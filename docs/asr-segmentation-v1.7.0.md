# 自动字幕怎样译得连贯、显示得舒服：1.7.0

**这次改进的目标是让中文保持完整意思，同时避免大段文字占满视频。** 分句首先服务于翻译理解；分页在中文译文产生之后进行，不把屏幕上的每一页重新当作一句翻译或朗读。

## 旧版为什么仍会割裂

复现旧版发现了两类不同的问题。

| 问题 | 复现例子 | 为什么会影响中文 |
| --- | --- | --- |
| 把新主语候选误当句界 | `the reason I wanted to share / this story … how easily / we can forget …` | 前半段缺少宾语，后半段丢失“分享这个故事的原因”这个关系。 |
| 切断转述或因果范围 | `they believed the bridge would collapse / and they would lose everything` | “他们认为会失去一切”容易变成译者直接陈述“他们会失去一切”。 |
| 用字符数平衡中文页面 | `电池续航更 / 长`、`出现在 / 面前` | 单词或紧密短语分到两页，阅读和语音都显得生硬。 |
| 原文和译文分别按比例翻页 | 中文较早出现的内容，在英文里可能位于句末 | 英中语序不同，字符比例不能说明两页表达了同一个意思。 |

不是所有旧样例都需要重新拆分。Nintendo 截图的四段叙述和 Netflix 截图的六段叙述继续保留；改进的是错误边界和译后的显示方式，而不是一味增加分段数量。

## 重新查阅的研究与字幕规范

| 来源 | 对本项目有用的结论 | 本版采用的设计 |
| --- | --- | --- |
| [Sen、Bojar、Haddow，2022：Simultaneous Translation for Unsegmented Input](https://arxiv.org/abs/2210.09754) | 错误的 ASR 分段会损害后续翻译，不能过度信任自动标点和句界。 | 不确定的从句保持完整；自定义服务可借助前后文理解当前段落。 |
| [Zhang 等，ACL 2022：Learning Adaptive Segmentation Policy](https://aclanthology.org/2022.acl-long.542/) | 分段需要兼顾意义、上下文和延迟，固定长度无法充分体现这些关系。 | 源文的语法保护优先于显示长度；显示长度只约束译后的页面。 |
| [Netflix：通用字幕规范](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215758617-Timed-Text-Style-Guide-General-Requirements) | 换行应尊重语法组，屏幕空间和可读性也需要考虑。 | 中文页面优先沿标点和词语边界，避免在紧密短语内部切开。 |
| [Netflix：简体中文字幕规范](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215986007-Chinese-Simplified-Timed-Text-Style-Guide) | 中文字幕有自身的显示与连续性要求，连续一句可以出现在相邻字幕中。 | 用页码表示同一句的连续页面，保留全部译文，不追加假的停顿或省略。 |

这些是设计参考，**没有声称复现论文里的训练模型，也没有把论文的指标算作本插件的成绩。** 两篇翻译论文的实验语言并非直接覆盖本项目的英语译简体中文场景，因此这里采用的是设计原则，再以本项目的回归样例验证。

Netflix 的固定字符数属于影视交付规范，本插件按播放器宽度和字号调整预算；也不照搬省略中文标点的排版风格，因为浏览器朗读需要标点来表达停顿。

## 本版实际处理流程

```text
明确标记为 ASR 的源字幕
        ↓
保留原词和时间，寻找完整的翻译单元
        ↓
整段翻译，保持条件、因果、否定和引语范围
        ↓
中文按标点与词语边界分页 ── 原文使用可信的句段对应关系
        ↓
沿当前朗读进度翻页，完整读完再进入下一段
```

### 1. 先保护英语里的意思关系

继续使用随包提供的 winkNLP 英语词性模型和本地规则。它是词性分析器，**不是完整依存句法或大语言模型**。

新版增加动宾、`how/why/whether/what` 补语、报告动词后的并列转述、因果与条件范围保护。比如 `share this story`、`how easily we can forget` 和 `they believed … and they would …` 不再因为后面像一个新主语而被轻易拆开。

短暂停顿也要看尾部：`until`、`real` 等仍在等待后文的词，后面出现两秒左右的停顿时，不把下一行直接视为新句。六秒以上的空白仍可结束一个源文块，避免跨越很长静默强行拼接。只凭文字不能可靠判断所有说话人变化。

无标点英语 ASR 的翻译输入补充句末句号，明确的倒装疑问补问号。**这不是完整标点恢复。** 保存、显示和导出的源字幕仍保持原词；不擅自修改 ASR 里的错词、漏词或名字。

### 2. 面向中文母语观众翻译

默认仍使用 Google，无需另配密钥。翻译请求使用完整源文单元，不把显示页面逐页送去翻译。

自定义服务的要求改为：准确理解后使用自然的中文语序；保持否定、条件、因果、引语归属、专有名词和数字；使用合适的中文标点；可以写成清楚的短句，但不能为变短拆断修饰或动宾关系。每段可附带前后各最多 400 字符的上下文，要求只译当前段，不重复上下文。直播不会假装取得尚未出现的后文。

Google 模式不会额外发送这两个上下文窗口；它没有本项目可控的系统提示。两种服务的行为不能混为一谈。

### 3. 再按中文习惯显示页面

分页改用浏览器 `Intl.Segmenter` 的中文词语边界和字素边界，优先中文句末标点、分号、逗号，再考虑词语边界。通过动态规划比较整段页面，避免仅选择当前最接近字符上限的一刀。

页面长度是软预算：必要时允许约 30% 的余量，以保留自然停顿。尽量不让 `的、把、被、更、因为、如果` 等悬在页尾，不把右括号或句末标点挤到下一页。正常页面预算从旧版最多约 80 字符降至最多约 48 字符，宽度较窄或字号较大时继续缩短，通常形成一到两行中文。

| 连续中文 | 新版两页显示示例 |
| --- | --- |
| 直到你亲眼看到这些熟悉的东西出现在面前，才会重新想起那些真实的回忆。 | ① 直到你亲眼看到这些熟悉的东西出现在面前，<br>② 才会重新想起那些真实的回忆。 |
| 如果你把左边这张图片和右边那张图片仔细对照，就会发现房间已经变了。 | ① 如果你把左边这张图片和右边那张图片仔细对照，<br>② 就会发现房间已经变了。 |
| 后来我发现，这家公司声称电池续航更长，但独立测试得出了不同的结果。 | ① 后来我发现，这家公司声称电池续航更长，<br>② 但独立测试得出了不同的结果。 |

这些例子使用较小的 24 字符软预算，说明自然边界优先。**一页可以是同一句中的完整分句，不代表它是脱离后文的独立判断。** 条件和后果仍属于同一个翻译与朗读单元；若要求每页都包含完整长句，长句仍会铺满画面。

极端长词、未知名字、缺标点文本或很小的显示区域需要折中；中文词语分析本身也有歧义。页面拼接严格保留所有原始译文字符，不靠省略内容解决长度问题。

### 4. 双语与朗读一起保持连续

Google 返回可信的源文／译文句段对时，保留并校验字符范围，用实际对应关系显示原文。它是粗粒度的句段对应，**不是逐词对齐**。译文页落在同一个句段内时，可以重复显示这个完整原文句段。

服务没有对应关系、范围不完整或无效时，显示完整源文单元。这样可能让原文稍长，但不再按中英文字符比例猜一段原文。自定义服务当前返回普通译文，使用这个完整源文后备方式。

中文页面按真实朗读字符进度切换，暂停时冻结；没有字符回调的声音仍用原有活动时钟估算。较长的 TTS 片段也使用自然词语和标点边界，片段比显示页更长，减少语音重置。完整模式继续逐句读完，视频照常播放，实际语速仍为基础倍率乘视频倍速。

同一份字幕同时从页面请求和网络捕获到达时，不再重复安装相同字幕，避免重新开始翻译和朗读。ASR 采用新缓存版本，自动避开旧结果；原生字幕缓存和用户设置保留。

## 验证结果与实译观察

- **114 项单元测试通过。** 包括动宾与补语、条件／因果／否定、转述范围、暂停间隔、中文词语与数字、括号及组合 emoji、上下文、翻译对应关系和缓存持久化。
- **Edge 集成检查通过。** Netflix 六段长句分页、Nintendo 四段无标点叙述、原生字幕条目保持，以及暂停／缓冲／恢复。检查记录完整字符顺序、零主动视频暂停／播放调用、倍率和音量保持。
- **Edge 原生中文语音静音检查通过。** 连续两次暂停恢复后得到真实结束回调；这不是晓晓在线声音的主观听感测评。
- **真实 Google 服务的 12 个样例请求成功。** 通过 Edge 发出，输出保存在本机 `dist/asr-redesign-report.json`。本机 Node 直连这次超时，不能把这次成功归给 Node 直连。
- **长中文分页检查。** 本机 6,800 字符测试约 18 ms、200 页，页面拼接恢复全文；这是合成样例的本机测量，不是所有设备的性能保证。

实译样例中，完整发送 `the reason I wanted to share this story …` 后，Google 返回“我想分享这个故事的原因是它表明我们很容易忘记年轻时帮助过我们的人。”，保留了前后关系；转述样例也保留“他告诉我”和“他们相信”的范围。

但 Netflix 样例中的 `poured one out` 仍被译成“倒了一个”，说明**分段改善不能替代译者对俚语的理解**。ASR 已识别错的词、专有名称以及翻译服务自身的直译，仍可能造成奇怪的中文。自定义服务的上下文和新版提示有助于这类问题，但本次未使用用户的付费模型做主观质量评测，不宣称已经解决所有翻译错误。

本次没有完成真实 YouTube 原视频从头到尾的有声听测。浏览器集成使用可复现字幕页面和替代语音设备，真实语音检查采用静音输出；这些证据与真人听感评价分别记录。

## 复现入口

```sh
npm test
npm run build:syntax
node tests/semantic-pages.cjs
node tests/asr-sentences.cjs
node tests/native-boundaries.cjs
node tests/playback-resume.cjs
node tools/evaluate-asr.cjs
```

最后一个命令默认离线检查公开样例，不上传字幕。需要观察真实翻译时使用 `--live`；Windows 上可加 `--edge`，通过已安装的 Edge 发出请求。`--baseline <旧版core.js>` 可比较旧版源文边界与中文页面。实译结果是观察记录，不自动生成准确率或人工质量分数。

## 仍严格保留的规则

人工／原生字幕、原生字幕的自动翻译和类型不明的字幕，保留原条目的文字和时间边界，不合并、不拆分、不分页。**只有明确标记为 ASR 的字幕使用上述分段与显示分页。**

更新为 1.7.0 后，在扩展管理页重新加载，再刷新 YouTube。无须恢复默认设置或清空全部缓存；ASR 旧版缓存自动避开。
